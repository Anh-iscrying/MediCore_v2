Tài liệu Kỹ thuật: Luồng Xác thực & Phân quyền (MC-03)
Dành cho: Frontend Developer (Next.js)
Công nghệ: Spring Boot Security + JWT + HttpOnly Cookie

1. Cơ chế xác thực (Authentication Mechanism)
Hệ thống sử dụng JWT (JSON Web Token) để xác thực, nhưng thay vì lưu ở localStorage, Backend đã cấu hình trả về qua HttpOnly Cookie để tăng tính bảo mật (chống tấn công XSS).
Thông tin Cookie:
•	Tên: accessToken
•	Loại: HttpOnly (Javascript không thể đọc được, trình duyệt tự quản lý).
•	Thời hạn: 24 giờ.
•	Cấu hình quan trọng: Frontend PHẢI bật withCredentials: true (nếu dùng Axios) hoặc credentials: 'include' (nếu dùng Fetch) để trình duyệt tự động gửi/nhận Cookie này.

2. Các API quan trọng
A. Đăng nhập (Login)
•	Endpoint: POST /api/v1/auth/login
•	Request Body: {"email": "...", "password": "..."}
•	Backend xử lý:
1.	Kiểm tra thông tin trong bảng auth_credentials.
2.	Nếu đúng, tạo JWT Token.
3.	Gắn Token vào Header Set-Cookie.
4.	Trả về thông tin User cơ bản trong JSON Body (để FE điều hướng nhanh).
B. Lấy thông tin người dùng hiện tại (Get Me)
•	Endpoint: GET /api/v1/auth/me
•	Mục đích: FE gọi API này ngay khi vào Dashboard để lấy dữ liệu "Sạch" từ Database (Tên thật, Role, PatientCode/DoctorID).
•	Backend xử lý: Đọc Token từ Cookie, tìm User trong DB và trả về JSON.
C. Đăng xuất (Logout)
•	Endpoint: POST /api/v1/auth/logout
•	Backend xử lý: Xóa Cookie accessToken trên trình duyệt. FE chỉ cần gọi API này rồi xóa user trong localStorage là xong.

3. Phân quyền dựa trên Vai trò (RBAC)
Backend đã gán tiền tố ROLE_ vào các Role. Bạn cần điều hướng trang dựa trên trường role nhận được từ API:
Giá trị Role	Trang đích (Redirect)	Quyền hạn
ADMIN	/admin/dashboard	Toàn quyền (Quản lý bác sĩ, chuyên khoa, import).
DOCTOR	/doctor/dashboard	Xem hàng chờ khám, lưu hồ sơ bệnh án.
PATIENT	/dashboard	Đặt lịch hẹn, xem lịch sử bệnh án cá nhân.

4. Lưu ý cho Frontend (Action Items)
1.	Fix CORS: Đảm bảo gọi API đến đúng http://localhost:8080/api/v1/...
2.	Gán dữ liệu thật: Thay thế toàn bộ "Alexander Carter" hoặc các nhãn "Mô phỏng" bằng dữ liệu lấy từ:
o	Object user trong localStorage sau khi Login.
o	Hoặc gọi API GET /auth/me.
3.	Xử lý lỗi 403: Nếu nhận được mã 403, hãy hiển thị Toast thông báo: "Bạn không có quyền truy cập" và điều hướng user về đúng Dashboard của họ.
4.	Header Authorization: Backend vẫn hỗ trợ nhận Token qua Header nếu ông muốn dùng song song với Cookie:
Authorization: Bearer <TOKEN>
